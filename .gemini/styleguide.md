# 리뷰 가이드

모든 리뷰 코멘트는 한국어로 작성한다.

## 이 저장소의 규칙

1. 모든 설계 결정은 `docs/adr/`의 ADR로 뒷받침되어야 한다. ADR 없이 새 결정(라이브러리 추가, 저장소 변경, 재시도 정책 등)이 코드에 들어오면 지적한다.
2. 모든 결정은 `docs/design/00-scope.md`의 FR 또는 NFR에 연결되어야 한다.
3. 수치는 로컬 측정값에서 출발한다. 측정 조건이 없는 수치는 지적한다.
4. 외부 호출(DB, Redis, 큐, 객체 스토리지, FFmpeg 프로세스)에는 타임아웃과 취소가 있어야 한다.
5. 메시지 소비, 업로드 완료 처리, 트랜스코딩 작업은 두 번 실행되어도 결과가 같아야 한다(멱등).
6. 상태 변경과 이벤트 발행은 원자적으로 묶여야 한다(Outbox, ADR-0010).
7. 문서와 주석에 긴 대시 문자(U+2014, U+2013)를 쓰지 않는다.

## 지적 우선순위

데이터 유실, 중복 처리, 장애 전파, 리소스 누수를 문체나 이름보다 먼저 본다.
