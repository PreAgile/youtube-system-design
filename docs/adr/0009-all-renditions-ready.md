# ADR-0009: 전체 대상 화질 준비 후 업로드 완료와 영상 준비 시간

| 항목 | 값 |
|---|---|
| 상태 | Accepted |
| 작성일 | 2026-10-10 |
| 결정일 | 2026-10-10 |
| 관련 FR/NFR | FR-1, FR-2, FR-3, NFR-5, NFR-7 |

대체 관계: ADR-0001·0002의 서비스 업로드 완료 용어, ADR-0002·0003·0004의 기준 화질 준비 p95 5분 전제, ADR-0006의 준비된 화질을 순차 공개하는 전제를 부분 대체한다. 기존 저장소 조회·폴링·자체 작업자·임대·시도별 결과 등록·CDN과 버전 경로 선택은 유지한다. 기존 ADR 본문은 당시의 결정 기록으로 보존한다.

## 1. 문제와 제약

기존 문제 카드는 원본 전송·검증 후 업로드 완료를 응답하고, 360p가 준비되면 시청 가능으로 전환하며 다른 화질을 나중에 추가했다. 사용자는 모든 대상 화질이 준비되어야 해당 영상을 업로드 완료로 표시하고 시청할 수 있어야 한다고 결정했다(FR-2, FR-3).

원본 전송 완료와 서비스 업로드 완료를 같은 말로 부르면 변환 시작 시점과 원본 보존 약속이 모호해진다(FR-1, NFR-7). 영상 준비 시간(NFR-5)도 기준 화질 하나가 아니라 전체 대상 화질 준비를 측정해야 한다. 실제 변환·대기 시간을 측정하지 않았으므로 기존 5분을 확정 목표로 주장할 수 없다.

## 2. 대안과 판단 기준

| 유력 대안 | 기준에 따른 장점 | 비용과 한계 |
|---|---|---|
| A. 360p 준비 시 공개하고 나머지 화질을 순차 추가 | 먼저 시청 가능해지고 고화질 작업 실패가 저화질 공개를 막지 않는다 | 초기 시청자는 일부 화질만 선택할 수 있다 |
| B. 대상 화질 전체 준비 후 업로드 완료·재생 가능으로 표시 | 시청 시작부터 대상 화질 전체를 선택할 수 있고 완료 조건이 명확하다 | 가장 늦은 화질까지 기다리며 하나의 최종 실패도 완료를 막는다 |

사용자는 B의 전체 준비 조건을 우선했다. 시간 지표는 원본 전송 시간과 그 이후의 영상 준비 시간을 분리한다. 변환 시간을 준비 지표에서 제외하면 실제 처리 대기를 설명하지 못하므로, 변환을 포함하고 수치 목표를 검증 후 확정하는 방안을 비교·선택했다.

## 3. 사용자 제안과 검토

- 사용자 제안: 360p·1080p 등 필요한 화질의 변환이 모두 성공하고 완전히 준비되어야 업로드 완료로 판단한다.
- 면접관 검토(LLM): 원본 전송 완료 → 처리 중 → 전체 준비 후 업로드 완료·재생 가능을 구분하고, 원본보다 높은 화질은 요구하지 않는 기존 조건에 따라 대상 화질을 정한다. 가장 늦은 화질까지 공개를 기다리는 비용이 있다.
- 사용자는 전체 준비 정책에 동의한 뒤, 변환까지 포함하면 p95 5분을 적용하기 어려울 수 있다며 지표 설정 방법을 물었다.
- 면접관 제안(LLM): 원본 전송 시간과 영상 준비 시간을 분리하고, 후자에는 작업 대기·원본 읽기·변환·결과 저장·매니페스트 발행과 재생 가능 상태 반영을 포함한다. 10분 이하·최대 1080p 조건에서 p95를 측정하며, 5분은 검증 전 후보값으로 두고 목표값을 검증 후 확정한다.
- 사용자는 이 방향을 선택하고 기존 문서를 동기화하도록 요청했다. 구현·측정 결과는 없다.

## 4. 결정과 이유

사용자가 B와 준비 시간의 측정 구간·목표값 검증 방식을 선택했다. 이유는 대상 화질 전체가 완전히 준비된 상태를 서비스의 업로드 완료로 판단하려는 것이다. 수치 목표는 실제 처리 시간을 검증한 뒤 확정한다.

- 원본 전송·검증·보존 조건을 충족하면 원본 전송 완료를 동기 응답한다. 영상은 처리 중이며 아직 서비스 업로드 완료나 시청 가능이 아니다.
- 대상 화질은 360p·480p·720p·1080p 중 원본 해상도 이하의 화질이다. 1080p 원본은 네 화질, 720p 원본은 세 화질 전체를 준비한다.
- 대상 화질 전체의 결과와 그 화질을 담은 매니페스트가 준비되어야 서비스 업로드 완료·재생 가능으로 표시하고 시청자에게 제공한다. 일부 화질만 준비된 목록은 공개하지 않는다.
- 화질별 작업·상태와 기존 시도 횟수 상한(3회)을 유지한다. 대상 화질 하나가 최종 실패하면 해당 작업과 영상은 처리 실패이며, 준비된 일부 화질만으로 공개하지 않는다.
- NFR-5는 원본 전송·검증 완료부터 전체 대상 화질과 매니페스트가 준비되어 재생 가능해질 때까지다. 작업 대기·원본 읽기·변환·결과 저장·매니페스트 발행과 상태 반영을 포함한다.
- 10분 이하·최대 1080p의 지원 입력 영상에서 p95를 측정한다. p95 ≤ 5분은 검증 전 후보값이며, 목표값은 대표 영상의 변환·작업 대기 시간 검증 후 확정한다. 10분 초과 영상은 별도로 측정하고 목표를 정한다.
- 원본 전송 시간은 업로드 시작부터 원본 전송·검증 완료까지의 별도 지표이며 파일 크기·네트워크 조건별로 본다. 수치 목표는 아직 정하지 않았다.
- NFR-7의 원본 보존 조건은 원본 전송 완료 응답 시점부터 적용하며, 전체 화질 준비를 기다리지 않는다.

## 5. 얻는 것과 감수한 비용

- 얻는 것: 서비스 업로드 완료와 시청 가능 조건이 일치하고, 시청 시작부터 대상 화질 전체를 선택할 수 있다. 원본 전송 성공과 변환 완료를 별도 상태로 설명할 수 있다.
- 비용: 일부 화질이 먼저 성공해도 가장 늦은 화질과 매니페스트 준비를 기다린다. 대상 화질 하나의 최종 실패가 서비스 업로드 완료를 막는다. 기존 360p 우선순위만으로 전체 준비 시간 목표를 충족했다고 판단할 수 없다.
- 작업별 상태 조회와 전체 완료 판정이 모두 필요하다. CDN에 캐시된 처리 중 응답은 전체 준비 이후에도 짧은 캐시 수명만큼 상태 반영을 늦출 수 있다.

## 6. 검증과 남은 불확실성

- 대표 입력의 길이·해상도·코덱별 화질 변환 시간과 CPU·메모리 사용량을 측정하고, 작업 대기·결과 저장·최종 발행을 포함한 준비 시간 분포를 검증한다. 아직 측정하지 않았다.
- 작업별 p95를 합하거나 단일 변환 시간만으로 전체 준비 p95를 주장하지 않는다. 최종 실패는 별도 실패율로 기록하고 준비되지 않은 영상을 성공 표본으로 취급하지 않는다.
- 기존 ADR-0002·0004의 처리 시간 5분 가정에 따른 폴링·임대 부하 계산은 예시이며, NFR-5 충족 근거가 아니다. 대상 화질 수와 전체 처리 시간을 반영해 다시 계산해야 한다.
- 원본 확정 중 장애와 재시도, 원본 전송 완료 기록과 작업 생성의 원자성, 오래된 작업자의 실패 보고는 후속 설계 항목이다.
- 전체 준비를 확인한 매니페스트 발행과 재생 가능 상태 갱신의 원자성, 최종 실패 후 남은 작업의 취소·성공 결과 보존·수동 재처리 정책은 별도로 결정해야 한다. 이번 결정은 그 구현 방식을 확정하지 않는다.
- 360p 우선 처리라는 기존 선택은 유지하지만, 전체 화질 준비 시간에 맞춘 스케줄링·확장 기준은 아직 정하지 않았다.

## 7. 재검토 조건

- 전체 준비를 기다리는 시간이 사용자에게 허용하기 어려울 정도로 길어 일부 화질 선공개가 요구될 때.
- 고화질의 최종 실패 때문에 공개되지 못하는 비율이 제품 요구에 맞지 않을 때.
- 입력 길이·해상도·코덱 범위 또는 측정 결과가 바뀌어 준비 시간 목표를 조정해야 할 때.
